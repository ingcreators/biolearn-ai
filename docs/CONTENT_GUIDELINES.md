# Content guidelines

## 基本方針

BioLearn の本文は、初学者がつまずきやすい点を先回りして説明します。専門用語は避けすぎず、日本語名、英語名、略語を併記して段階的に慣れてもらいます。

## 文体

- 日本語本文は自然で簡潔に書く。
- 断定しすぎず、学習段階に応じて「まずは」「ここでは」と範囲を示す。
- 読者を不安にさせる表現や過度に扇情的な表現を避ける。
- 医療上の診断、治療、個別の判断を促す表現を避ける。

## 科学的正確性

- 生命科学の基礎概念は、最新性よりも標準的で再利用しやすい説明を優先する。
- 研究が進行中の話題は、確立した事実と仮説を区別する。
- 遺伝子、疾患、検査に関する説明では、個人の健康判断に直結する書き方を避ける。

## Lesson template

基礎概念を扱うレッスンは、目次だけで学習の流れが分かる構成を使います。

1. この記事で学ぶこと
2. 見出しなしの「とは何か」説明
3. 見出しなしの `LessonFigure`
4. `なぜ{概念名}の視点が重要か`
5. `どんな{概念名}があるか` または `どんな種類があるか`
6. `{概念名}はどう調べるか` または `どう観察・測定するか`
7. `{概念名}の変化は何につながるか`
8. `論文や実験ではどう出てくるか`
9. `どんな点でつまずきやすいか`
10. `重要用語`
11. 確認問題
12. 次に読む記事

記事の性質により不要な節は省略してよいですが、定義、重要性、論文や実験との接続、つまずきやすい点、重要用語は原則として残します。Figure の読み方、論文読解、リソース、パス案内のように記事の目的が明確に異なる場合は、そのカテゴリに合う構成を優先します。

## 冒頭の「とは何か」説明

基礎概念、実験手法、統計、バイオインフォマティクス用語を説明する記事では、`LearningGoals` の直後、`LessonFigure` の前に、ページタイトルの中心語に対する「xxxとは何か」の説明を置きます。本文内に `## xxxとは何か` という見出しは作らず、ページタイトルと冒頭本文で役割を分担します。

- 1段落目は、中心語の一文定義にします。初学者が「何を指す言葉か」をすぐ言える粒度にし、例外や詳しい分類を詰め込みすぎません。
- 2段落目は、定義を少し広げます。代表的な構成要素、働き、研究での見方、他の基礎概念との関係のうち、その記事の理解に必要なものを1つか2つだけ補います。
- 分量は原則として2段落、合計2〜4文程度にします。短すぎると図の前に概念が立ち上がらず、長すぎると後続の `なぜ...重要か` や `どんな...があるか` と重複します。
- 図の後ろに、同じ定義や「xxxとは何か」の基礎説明を繰り返しません。図の後は、重要性、種類、調べ方、変化の意味など、次の役割の本文へ進めます。
- 中心語そのものは本文中で無理に自己リンクせず、`重要用語` の `GlossaryTable` で用語集へ接続します。冒頭で周辺語に glossary リンクを付けた場合、その語は記事内の通常本文で初回リンク済みとして扱い、後続本文では同じ語を繰り返しリンクしません。
- 冒頭説明は、その記事の説明対象に集中します。医療上の診断、治療、個別判断に見える話題や、本文で扱わない専門的な例はここに入れません。

## Terminology sections

- 基礎概念記事では、「英語表記と略語」を独立節として残さず、`重要用語` の `GlossaryTable` に統合する。
- `GlossaryTable` には、日本語名、英語名、必要な場合のみ略語、1文説明、用語集ページへのリンクを入れる。
- 「重要用語」は、その記事を理解するための短い概念説明として使う。英語名の再掲だけにせず、1文で役割や意味を書く。
- 略語が一般的でない場合は項目自体を省くか、コンポーネントの表記に合わせて無理のない形にする。無理に略語を作らない。

## Concept sections

- 種類、代表例、具体例は、初学者が本文の概念を実験、解析、Figure、身近な研究場面へ移せるように書く。
- `どんな点でつまずきやすいか` では、似た用語との差と解釈上の注意をまとめる。必要に応じて `### 似た用語との区別` と `### 解釈の落とし穴` を使う。
- `論文や実験ではどう出てくるか` は、Methods、Results、Figure legend、Supplementary、典型的な図表での現れ方を説明する。断定的な研究主張ではなく、読み方の手がかりとして書く。

## 確認問題の作成・編集基準

確認問題は、記事末尾の小テストではなく、`この記事で学ぶこと` を読者が理解できたかを確かめるために作ります。単語の暗記だけでなく、概念の境界、実験やFigureでの見え方、初学者が混同しやすい点を問います。

- 各問題は、原則として `LearningGoals` のいずれかに対応させる。複数の目標を1問に詰め込みすぎず、どの学習目標を確認しているか説明できる状態にする。
- 問題文は選択式に合う形にする。「説明してください」「挙げてください」「一文で説明するとどれですか」のような自由記述風の文ではなく、「最も適切なのはどれですか」「読み取りとして適切なのはどれですか」のように選べる問いにする。
- 正答は本文の範囲内だけで判断できる内容にする。本文で扱っていない専門知識、細かい例外、医学的な診断・治療判断は問わない。
- 誤答選択肢は、明らかにおかしいものではなく、初学者が迷いやすい誤解を使う。例として、「DNAそのものがすぐ機能を実行する」「RNAはmRNAだけを指す」「遺伝子は必ず1つのタンパク質だけを作る」「細胞は分子の文脈なしに理解できる」のような、本文中のつまずきポイントに対応させる。
- 誤答はすべて同じ種類の引っかけにしない。定義の混同、階層の混同、測定値の読み違い、因果の言いすぎなど、記事の内容に合う誤解を分散させる。
- 選択肢は原則4択にする。5択は、自然で本文範囲内の誤答を5つ目まで作れる場合だけ使う。数を増やすために不自然な選択肢や本文外の知識を混ぜない。
- 問題数は、標準的な記事では4問を目安にする。基礎中の基礎になる記事、後続記事の前提になる記事、`LearningGoals` が多い記事では5問まで増やしてよい。短い導入記事や読み物寄りの記事では3問でもよいが、学習目標を十分に確認できるかを優先する。
- 1問ごとに、正答だけでなく誤答も短すぎない表現にする。ただし、選択肢同士の長さが極端に違って正答が見えないようにする。
- 既存の確認問題を編集するときは、問題数を増やす前に、まず `LearningGoals` との対応、本文範囲内か、誤答が実際の誤解になっているかを見直す。
- 出題順と選択肢順は表示側でランダム化されるため、選択肢の位置や問題の並びに依存した説明をしない。

## 基礎概念記事の再構成手順

`fundamentals/molecule.mdx` で行った修正を、他の基礎概念記事へ横展開するときは次の手順を使います。目的は、本文に埋もれている定義、重要性、具体例、実験での現れ方、つまずきやすい点を整理し、目次だけで学習の流れが分かる状態にすることです。ただし、ページタイトルと同じ文言の見出しを本文内に追加して重複させないようにします。

### 1. 見出しを問いの流れに揃える

基礎概念記事では、できるだけ次の順序を基準にします。記事の性質により不要な節は省略してよいですが、定義、重要性、論文や実験との接続、つまずきやすい点、重要用語は原則として残します。ページタイトルはすでにヘッダーと目次に出るため、本文内ではページタイトルと同一の `## {概念名}とは何か` を作らず、LearningGoals の直後に見出しなしの「とは何か」説明を置きます。

1. 見出しなしの「とは何か」説明
2. `LessonFigure`
3. `なぜ{概念名}の視点が重要か`
4. `どんな{概念名}があるか` または `どんな種類があるか`
5. `{概念名}はどう調べるか` または `どう観察・測定するか`
6. `{概念名}の変化は何につながるか`
7. `論文や実験ではどう出てくるか`
8. `どんな点でつまずきやすいか`
9. `重要用語`

見出しは名詞句と疑問形が混在しすぎないようにし、読者が「次に何を読むのか」を予測できる表現にします。

### 2. 冒頭の本文を分解して移動する

冒頭に長い基礎解説がある場合は、そのまま残さず、役割ごとに移動します。

- 「とは何か」説明は LearningGoals の直後に見出しなしで置く。
- 図は「とは何か」説明の直後に置き、図のあとに同じ定義や基礎説明を繰り返さない。
- 重要性や見方の説明は `なぜ...重要か` に移す。
- 種類や代表例は `どんな...があるか` に移す。
- 実験手法、測定対象、観察方法は `どう調べるか` に移す。
- 細胞、個体、表現型、解析結果へのつながりは `変化は何につながるか` に移す。

移動後は、同じ内容を別の段落で繰り返していないか確認します。特に「とは何か」の定義は、ページタイトル、冒頭文、本文で重複しやすいので注意します。

### 3. 似た概念と誤解は統合する

`よく混同される概念` と `よくある誤解` が近い内容になっている場合は、`どんな点でつまずきやすいか` に統合します。中では次の小見出しを使います。

```md
## どんな点でつまずきやすいか

### 似た用語との区別

- AとB: ...

### 解釈の落とし穴

- ...
```

「似た用語との区別」では、用語の境界を短く説明します。「解釈の落とし穴」では、実験結果やFigureを読むときに断定しすぎないための注意点を書きます。

### 4. 用語は `重要用語` に集約する

`英語表記と略語` を独立節として残すより、`重要用語` に統合し、`GlossaryTable` で表示します。各項目には日本語、英語、必要な場合のみ略語、1文説明、用語集ページへのリンクを入れます。

```mdx
## 重要用語

<GlossaryTable
  terms={[
    {
      term: '分子',
      english: 'molecule',
      description: '原子が結びついてできた物質のまとまり。',
      href: '/glossary/molecule/',
    },
  ]}
/>
```

`重要用語` は記事理解に必要な語彙の一覧として使います。単なる周辺リンク集に見える `関連用語` という見出しは、記事本文内では原則使いません。

用語集ページがない用語を表に入れる場合は、先に `src/content/docs/glossary/{slug}.mdx` を作成し、`src/data/glossary.ts` の該当カテゴリにも追加します。

### 5. 本文中の用語リンクを絞る

本文中の glossary リンクは、用語集ページがある語を、記事内の通常本文で初めて登場した箇所だけに付けます。同じ語を同じ記事内で繰り返しリンクしません。`LearningGoals`、`LessonFigure` の `alt`、`title`、`caption`、`Quiz`、`GlossaryTable`、`NextSteps` などのコンポーネント内テキストは本文中の初回とは数えず、読者が通常の本文として読む段落や箇条書きでの初回を基準にします。

記事タイトルと同じ中心用語は、本文中で無理に自己リンクせず、`重要用語` の `GlossaryTable` で glossary へ接続します。

語の一部だけを glossary リンクにしません。たとえば `デオキシリボ核酸` の中の `核酸`、`RT-qPCR` の中の `PCR`、`遺伝子発現` の中の `遺伝子` のように、別のまとまりとして読まれる表現の一部だけをリンクすることは避けます。必要なら文を少し言い換え、リンクしたい語が独立して読める形にします。

用語リンクは本文の読解を助けるための補助導線とし、記事内の正式な用語整理は `重要用語` の `GlossaryTable` に集約します。

### 6. 次に読む記事から用語リンクを外す

記事末尾の `NextSteps` は、次に読むレッスン記事への導線に絞ります。用語へのリンクは `重要用語` の `GlossaryTable` に集約し、`NextSteps` には入れません。

### 7. 見た目と階層を確認する

見出し階層を変更したら、本文上で `h2` と `h3` の見え方に差があるか確認します。`どんな点でつまずきやすいか` のような `h2` と、その下の `似た用語との区別` のような `h3` が同格に見える場合は、共通CSSで調整します。

### 8. 検証する

記事を修正したら、少なくとも次を確認します。

- 目次の見出しが重複していない。
- 冒頭の定義が同じ言い方で二重になっていない。
- `GlossaryTable` のリンク先が存在する。
- `NextSteps` がレッスン記事だけを指している。
- 医療上の診断、治療、個別判断に見える表現がない。
- `npm run check` または `npm run build` が成功する。

## Lesson figures

- 各レッスンでは、冒頭の見出しなしの「とは何か」説明の直後に `LessonFigure` を置き、中心概念を1枚の教材イラストで補足する。
- 図解画像は `public/figures/{lesson-slug}-concept.jpg` に置く。ファイル名は英語小文字 kebab-case にする。
- 新しい `LessonFigure` 画像は、原則として既存のAI生成フローを使う。記事本文、`alt`、`title`、`caption` を整えた後に `npm` スクリプトではなく `scripts/build-figure-prompts.mjs` で共通プロンプトを生成し、必要な対象だけを `tmp/figure-prompts/batch.jsonl` から抽出して画像生成にかける。生成後は `scripts/apply-generated-figures.mjs` と同じ変換条件（1536×864、JPEG quality 86、mozjpeg）で `public/figures/` に配置する。
- 共通プロンプトは `scripts/build-figure-prompts.mjs` の `sharedPrompt` を正とする。個別に別スタイルのプロンプトを作らず、記事側の `LessonFigure` の説明で図の意図を調整する。
- 画像内には日本語ラベルや長い説明文を入れすぎない。正確な説明は本文、`alt`、`title`、`caption` で補う。
- 画像はオリジナル生成または利用許諾が明確なものだけを使う。外部画像や著作権不明素材は使わない。
- 医療上の診断、治療、個別判断を連想させる画像表現は避け、学習用の概念図として作る。
- 生成した元画像が大きい場合は、Web表示用に軽量化した `.jpg` を使う。目安として1枚あたり200KB前後に収める。

## Links

- 関連ページへの内部リンクを必ず用意する。
- 外部リンクを使う場合は、信頼できる機関、教科書、論文、公式ドキュメントを優先する。
